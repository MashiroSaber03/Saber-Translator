## 复查修复的问题

| 问题 | 本次处理 | 验证 |
|---|---|---|
| 候选已经安装，下一次启动校验失败时，没有覆盖立即回滚 | 存储准备失败同时处理 installed 候选，恢复旧数据 | 候选索引损坏后重启的回归测试 |
| 桌面配置等初始化失败发生在后端启动前，未进入启动失败恢复 | Desktop 使用同一启动保护上下文，异常路径包括 installed 阶段 | 桌面构建异常注入测试 |
| 已提交后，删除门禁或目录标记被 Windows 拒绝，可能阻断服务 | 运行准入读取已落盘 committed 状态；标记删除纳入可重试清理 | 两种标记删除失败测试、业务仍可用断言 |
| 恢复记录丢失或残缺时可能将暂时缺失的数据根当作新目录 | 拒绝缺失记录、无对应记录的门禁和多个未决操作，不猜测恢复 | 目录移出后删除日志、孤立门禁测试 |
| 待验收候选被另一运行模式打开时，恢复逻辑可能修改它 | 操作记录携带 profile，先核验模式再恢复 | 模式不匹配不改变候选的测试 |
| 仅有通用 JSON 解析，不能覆盖桌面配置、插件和向量引用 | 固定版本校验统一注册到 VERSION_VALIDATORS；补桌面配置、插件目录哈希及 ready 集合校验 | 无效桌面 JSON、缺失 ready 向量集合测试 |
| 结束旧渲染执行时，页面仍可能显示 rendering | 同步收敛页面为 render_failed，保留已有文档与资产 | 页面状态投影测试 |

历史格式规则仍位于独立转换器中，没有向业务 Repository 加入历史兼容分支。3.5.0 是首个生产基线，生产迁移注册表仍为空。

## 方案逐项核对

| 方案要求 | 结果与证据 |
|---|---|
| 三段式项目/存储版本一致 | version.json 为唯一发布来源；整数三元组比较；数据库明确记录 storage_version；补丁升级和数值排序测试通过 |
| 每个版本明确迁移或空迁移、支持跳版本 | 相邻链、纯空链、混合链测试通过；发行测试核对全部已声明版本的完整路径、DDL 和固定规则 |
| 无版本、较新版本、缺路径、模式不匹配拒绝 | 自动化测试通过；无版本数据还进行了真实桌面提示和原库字节哈希验证 |
| 当前版本仍校验结构 | 列、外键、索引、约束及 JSON 校验；当前版本结构损坏测试通过 |
| 独立 CLI | 源码和打包 EXE 的 check / upgrade / --version 验证通过；check 不创建新目录或备份 |
| 独占权在数据根之外 | OS 文件锁与 PID + 创建时间校验；打包程序运行时，另开转换器 upgrade 被拒绝 |
| 完整副本、SQLite 一致性备份 | 文件独立复制和哈希检查；SQLite backup API；真实漫画资料转换后逐项比较一致 |
| 提交前业务门禁 | API 健康检查可用而其他请求返回 503 的测试通过；Worker 在提交前不进入任务/维护循环 |
| API 与 Worker 均就绪后提交 | 源码桌面、真实子进程测试、打包 EXE 桌面均完成验证 |
| 提交前回滚、提交后不回滚 | 复制、转换、验证、两次目录重命名之间、安装、启动、提交边界异常注入测试通过 |
| 初始化中断可重试 | 在临时位置完成初始化后发布；种子初始化失败后的重试测试通过 |
| 未完成任务结束，成果保留 | Job/Item/Step 的终态、检查点清除和完成成果保留测试通过；Operation、执行身份及派生状态按固定规则收敛 |
| 未启动后端时保留备份 | 实机观察 installed 阶段，backup 存在 |
| 成功后自动删除本次及历史待清理备份 | 源码及 EXE 实机均进入 cleaned，backup 消失；不需要确认弹窗 |
| 清理失败持续重试 | 异常注入测试及真实 Windows 打开文件句柄阻止删除测试通过，关闭句柄后重试完成 |
| 用户备份不被删除 | 独立用户备份保留、身份不匹配拒绝删除、清理范围边界测试通过 |
| 打包资源与版本检查 | 按 app.spec 构建测试 EXE 成功；版本清单、固定 SQL、四种运行角色和转换器入口探测通过 |

## 实机操作与数据保留

全部操作使用单独建立的测试目录。用户原先运行于 5000 端口的服务及原数据目录未被修改。

1. 使用 Windows 桌面控制工具打开测试桌面，点击启动后端，确认 API、Worker 和事件流正常。
2. 从桌面打开 Edge 网页，创建“存储升级实机验收”书籍和“第一章：重启后保留”章节。
3. 文件选择阶段曾被电脑控制工具中止；用户随后手动导入 24 张图片，之后继续验收。
4. 通过网页编辑器手工绘制气泡，写入原文及“存储验收：升级后保留”，确认本地渲染为 ready。
5. 点击桌面重启，重新加载网页，译文和译图保留。随后停止测试后端并关闭测试桌面，保留原测试数据。
6. 在测试数据的副本上添加测试专用旧字段和旧版本标记，通过测试迁移函数删除该字段并转换到 3.5.0。
7. 候选安装后先打开桌面而不启动后端，确认备份仍在；再点击启动后端，确认 API/Worker 就绪、阶段为 cleaned、备份目录被自动删除。
8. 重新加载章节网页，原图、译文和译图仍可读取。
9. 构建 EXE 后，在另一份同样的候选数据上重复桌面启动与自动清理验收；打包程序网页也能读取原章节和译文。
10. 打包桌面运行期间，另行运行独立转换器 upgrade，返回数据目录已被占用的错误，正常运行的实例不受影响。
11. 对另一个无版本旧库启动桌面，实际显示拒绝原因和诊断目录；原 SQLite 文件的 SHA-256 前后相同。
