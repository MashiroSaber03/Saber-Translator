## 1. 审计基线与结论

- 目标方案：`docs/refactor/backend-first-architecture-plan.md`
- 重构前基线：`dev`（`4db2d8ab`）

结论：方案的主架构已经落地。持久业务状态、长任务编排、AI 调用、资产管理、恢复与一致性均以后端为权威；浏览器主要承担交互状态、编辑画布、选择状态和虚拟化显示。本轮审计前仍残留一些“数据已在后端，但加载方式/并发控制仍像旧前端”的问题，现已修复。

当前没有加入身份验证；默认启动仍可监听局域网。按项目要求，图片、修复蒙版、Studio 附件、字体、文本导入、漫画容器和 Insight 源图均不再按文件字节或像素维度拒绝。仍保留格式有效性、路径穿越、归档特殊文件、压缩比和条目数等与媒体尺寸无关的校验。

## 2. 当前整体运行架构

```text
Launcher（监督、健康检查、重启、epoch 注册）
├─ API 进程
│  ├─ CRUD / 查询 / 分页 / 媒体响应 / SSE
│  ├─ 上传流式落盘、格式验证、缩略图
│  ├─ DurableOperationExecutor（最多 4 个交互型远程/CPU operation）
│  └─ DurableRenderExecutor（权威渲染）
└─ Worker 进程
   ├─ 全局持久 FIFO Job 调度
   ├─ 翻译、Insight、向量、网页导入、容器导入/导出
   ├─ 插件阶段与插件 Agent
   ├─ 本地模型生命周期 / 显存释放
   └─ 临时文件清理、资产 GC、孤儿对象修复

共享：SQLite WAL + 不可变对象目录 + Chroma 向量代际 + temp/runtime/logs
通知：SQLite 持久 job_events + 单一 SSE 连接
```

### 2.1 进程边界

- Launcher 是唯一监督者，负责 API/Worker 子进程、健康探测、有限重启和 epoch 租约。
- API 不导入 Worker 的本地模型、向量和插件执行模块。API 中仍有两类后台执行器：交互型 operation（修复、单气泡远程翻译、Studio 生成/聊天/摘要）和权威渲染；它们都有数据库状态、epoch fencing 和并发上限，不依赖页面存活。
- Worker 运行单一全局 FIFO 队列，任务步骤和 checkpoint 持久化。并行模式是一个任务内部按资源池并行，不会让多个顶层任务无界争抢模型。
- API 与 Worker 不靠浏览器内存传递状态，而是通过 SQLite、对象资产和冻结任务配置协作。

### 2.2 一致性与恢复

- 所有可变文档使用 revision/CAS；旧 revision 会冲突，而不是静默覆盖。
- 创建命令使用 Idempotency-Key；重放检查在可变资源重新解析之前完成。
- 任务冻结书籍、章节、页、资产 checksum、设置 revision、Provider/credential version、提示词和插件快照。
- Worker attempt 带 epoch/attempt fence，旧进程即使迟到也不能发布结果。
- 暂停/取消在安全点生效；重启后的 running 状态可变为 interrupted 并继续。
- SSE 事件先持久化，前端断线后可从 lastEventId 续接；内存 broadcaster 只负责及时唤醒。

## 3. 后端、浏览器与纯前端职责

| 类别 | 当前职责 |
|---|---|
| 后端权威 | 书籍/章节/页、图片资产、气泡文档、翻译约束、任务、分析结果、派生概览/时间线、向量代际、笔记、续写、Studio 文档/会话、设置、凭据版本、插件、导出产物 |
| 浏览器参与但后端落盘 | 文件选择后逐个上传、页面/气泡编辑、修复蒙版提交、续写表单与提示词自动保存、网页导入候选选择、任务操作 |
| 纯前端 | 当前标签、弹窗、选择/展开状态、主题、快捷键、滚动位置、画布命中测试/拖拽、虚拟窗口计算、尚未提交的输入字符 |
| 不可避免的浏览器工作 | File/drag-drop 入口、Canvas/DOM 显示、下载触发、可视区域测量和图片解码显示 |

浏览器不再持有可恢复任务队列，不在本地串联 OCR→检测→翻译→修复→渲染，也不保存唯一副本的业务文档。

## 4. 各页面功能与数据流

### 4.1 书架

- 后端：书籍/标签查询、章节聚合、封面资产、创建/删除/排序、批量翻译任务创建。
- 浏览器：搜索条件、排序选择、选中书籍和弹窗状态。
- 加载：书籍量预期较小，列表当前不分页；章节统计改为 SQL 分组查询，同时保留空章节，避免逐章 N+1。
- 本轮修复：批量操作只提交 `bookIds`，后端在同一权威快照中解析章节/页；首次加载中独立请求并行。

### 4.2 翻译工作区

- 后端：上传租约、临时落盘、图片验证/缩略图/对象发布、页面文档、术语与不翻译词、任务冻结、OCR/检测/翻译/修复/渲染、文本导入预览/提交、导出。
- Worker：批量翻译流水线和本地模型步骤；配置可选择顺序或受控并行。
- API operation：交互式单气泡远程翻译、页面修复和权威渲染。
- 浏览器：文件选择后顺序上传；气泡的拖拽、选择、局部编辑和修复蒙版绘制；变更通过 revision 操作提交。
- 网页导入：抓取、候选解析、下载、预处理、缩略图和提交均在后端；前端只分页展示与选择。本轮补齐候选/事件分页、全局计数和有界顺序提交。

### 4.3 阅读器

- 后端：一次返回轻量页元数据和 source/translated 媒体 URL；媒体按需响应。
- 浏览器：阅读模式、原图/译图切换、快捷键、当前页和可视区域。
- 性能：DOM 只挂载可视窗口及 overscan；可变高度列表使用前缀 offset + 二分查找，页 ID 到序号使用 Map，不再每次滚动线性扫描全书。

### 4.4 漫画分析（Insight）

- 页面分析：Worker 按冻结页资产调用 VLM，规范化后逐页发布；失败页可单独重试，完整/章节/选页/仅失败模式有精确状态。
- 页面树/详情：章节元数据与页摘要由后端分页提供，展开章节才取页；详情按需取。
- 概览：后端从精确 analysis fingerprint 读取结果，单次聚合模板和所需层；前端只选择模板、发任务和展示。
- 时间线：后端版本化构建，事件和角色分别游标分页；只返回当前页引用的缩略图，并按 enhanced→compressed→simple 回退。
- 问答：后端完成检索、可选 rerank、上下文构造、模型流式调用和持久会话；单候选不再启动 reranker；前端按 SSE 增量渲染并用 RAF 合并刷新。
- 向量：Chroma 使用 generation 构建，只有完成代际才切 active；暂停/取消和旧 Worker 都不能发布半成品。
- 笔记：后端持久化、游标分页；前端缓存有上限，并用请求世代阻止切书后的迟到响应污染。
- 续写：项目冻结“有序页输入 + fingerprint”，支持 page-scoped 组合分析，不再错误要求 book-level analysis head。角色、形态、脚本、逐页剧情、提示词、图片版本和导出全部后端化。浏览器只挂载当前步骤；自动保存统一串行，切页/卸载前强制 flush。
- 设置：Provider、提示词和批量参数后端持久化；弹窗只挂载访问过的标签页。

### 4.5 Character Studio

- 后端：文档、候选、资源、聊天会话/消息、附件资产、导入/导出、诊断、AI operation 和版本冲突。
- 浏览器：字段编辑、当前文档/面板/消息输入和预览。
- 性能：文档与资源缓存改为有界 LRU；删除时主动失效；图片上传先流式落盘再校验/发布，不在 API 中先复制成整块 bytes。

### 4.6 任务中心

- 后端：队列/历史、批次、步骤、进度、失败项、产物、暂停/继续/取消/重试、事件历史。
- 浏览器：一个全局 EventSource，多个页面订阅同一 store；事件突发时只保留一个在途刷新，并合并后续 dirty refresh。
- 加载：历史分页、详情按需展开、较早事件按需加载；任务继续运行与页面是否打开无关。

### 4.7 设置与插件

- 后端：设置 revision、Provider 配置、credential version、统一提示词、字体资产、插件包/配置/启停/阶段执行。
- 浏览器：表单和测试操作；只有访问过的设置页签才挂载复杂组件。
- 插件收到冻结上下文和资产 ID；大媒体资产读取不再保留 64 MiB 门槛。

## 5. 存储结构

### 5.1 SQLite

- 单库按领域分表：content、operations、jobs、settings、plugins、Insight、Studio、continuation、web import、vector generations 等。
- WAL、foreign keys、busy timeout；写操作保持短事务。
- 大 JSON 只用于有明确版本边界的文档/快照，查询热点仍有独立列和索引。

### 5.2 对象资产

- 原图、缩略图、译图、蒙版、封面、字体、Studio 附件、续写图和导出统一进入不可变对象目录。
- 数据库保存 asset ID、相对路径、SHA-256、MIME、尺寸和完整性状态。
- 发布流程为 staging → journal → 原子移动 → 绑定业务行；崩溃恢复和两阶段 GC 可处理孤儿或半提交对象。

### 5.3 向量与临时数据

- Chroma 按 book/generation 隔离，active generation 原子切换。
- `temp` 保存上传、网页导入和容器提取中间物；Worker maintenance 按 TTL 清理。
- 本轮运行数据、SQLite、向量与日志保留于 `.tmp/manual-e2e-019fcabd/`，进程已停止。

1. SSE 单连接、单飞刷新与事件合并，避免事件风暴触发重复全量请求。
2. 阅读器可变高度虚拟化从线性扫描改为前缀和二分；页索引改 Map。
3. Insight 页树、时间线、笔记、续写参考图、网页导入候选和事件补齐分页/加载更多。
4. Insight 初始独立请求并行；设置与续写步骤懒挂载。
5. 最近分析、概览输入和章节统计消除 N+1/重复扫描。
6. 派生上下文按最高所需摘要层、embedding 分批、单候选跳过 reranker。
7. QA 使用统一 async transport，完整流调用有墙钟超时；浏览器增量渲染合帧。
8. 时间线只绑定被当前页引用的缩略图，并缓存 URL 解析。
9. Studio、续写表单/状态、笔记与页详情缓存设置上限并在删除/切书时失效。
10. 上传由浏览器顺序发送，API 逐块落盘；Studio 和容器图片不再先整块复制进内存。

14. 零张续写生成图时禁用导出，避免必然 409 的无效任务。
15. 图片/附件/容器的字节拒绝和 Pillow 像素阈值移除；归档图片改流式发布。

## 7. 与方案的差异和剩余风险

- 方案的核心后端化边界已经满足；当前不是所有工作都只在 Worker：交互型 operation 和权威渲染按设计由 API 的持久执行器承担，并发上限为 4。这不依赖浏览器，但应与全局 FIFO Job 区分。
- 书架列表仍不分页，是基于“本地书库较小”的有意简化；若未来达到数万本，应再增加游标分页，而不是现在预先复杂化。
- 按明确要求不设置媒体字节/像素门槛，因此单个极端图片在 Pillow 解码、VLM base64 编码或 JSON/base64 Studio 导入阶段仍可能消耗大量后端内存。这是“不拒绝大文件”的必然代价；当前通过流式落盘、顺序上传、有界并发和缩略图/虚拟化控制常规峰值。
- 外部 Provider 仍可能超时。实测一次无剧透概览在 300 秒无响应后正确落为 `completed_with_errors`，任务中心可查看失败项并重试；Worker 未卡死。该次是供应商无响应，不是本地队列失效。
- 局域网仍完全开放且无认证，这是明确产品边界，不作为缺陷处理。
